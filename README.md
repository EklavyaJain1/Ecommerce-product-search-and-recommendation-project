# ShopMind — Ecommerce Product Search & Recommendation

**Repository:** `ecommerce-product-search-and-recommendation`

A full-stack ecommerce storefront written in Python where every core interaction is
backed by a named data structure or algorithm: prefix-trie autocomplete, BM25
inverted-index search, bounded-heap top-K ranking, merge-sort ordering, and
cosine-similarity recommendations. The storefront is a light, editorial retail
interface with a cart, filters, deep-linkable state and a product quickview.

No machine-learning dependencies, no database, no build step — Python 3, Flask and
the standard library.

## Overview

ShopMind serves a 126-product catalogue across six departments (Beauty 24, Books 24,
Electronics 20, Fashion 20, Home & Kitchen 20, Sports & Outdoors 18) from a single
Flask process. The catalogue is generated deterministically, then indexed three ways at
startup: a character trie for autocomplete, an inverted index for search, and sparse
term vectors for recommendations.

The point of the project is that the retail features and the algorithmic machinery are
the same thing. Typing `head` finds headphones because the trie completes the prefix;
`cast iron` ranks correctly because BM25 weights term rarity; the trending rail is a
bounded heap; every sort control is a stable merge sort.

**Stack:** Python 3.12 · Flask 3.1 · vanilla JavaScript (no framework, no build step)

## Features

### Storefront

- Sticky header with search, department navigation, cart badge and quick actions
- Live search-as-you-type dropdown showing matching products, term suggestions and a
  result count, with full keyboard navigation (arrows, `Enter`, `Escape`, `/` to focus)
- Filter rail: department, price range, minimum rating, in-stock only
- Sort by relevance, price, rating, newest or trending; "load more" pagination
- Product cards with derived badges (save %, new, best seller, sold out), star ratings,
  compare-at prices, colour swatches, stock urgency and shipping notes
- Product quickview: product photo or illustration, specifications, shipping/returns/materials
  accordions, and cosine-similar "You May Also Like"
- Cart drawer with quantity steppers, live subtotal and a free-shipping threshold
- "Recommended For You" rail that adapts to the products you open
- "Trending This Week" rail ranked by rating, review volume and recency
- "How Search Works" panel reporting live index statistics and the complexity class of
  each component

### Engine

- Prefix-trie autocomplete with weighted, popularity-ranked completions
- BM25-scored inverted-index search over weighted fields — the name is doubled at
  weight 3 (a 6× term-frequency boost), brand/type/category at weight 2, tags at
  weight 2, and the description at weight 1
- Trie-backed prefix expansion so partial words match (`head → headphones`,
  `espres → espresso`, `cast ir → iron`), scored at half weight so exact matches rank first
- Bounded-heap top-K selection for results and trending
- Item-to-item cosine similarity over sparse term vectors
- Hybrid personalised feed: `0.55 × taste + 0.25 × department affinity + 0.20 × trending`,
  with a trending cold start for empty history
- Per-request latency reporting surfaced in the UI

## Architecture

```
                        ┌──────────────────────────────┐
  browser ── HTTP ──▶   │  Flask (app.py)              │
                        │  routes · indexing · wiring   │
                        └───────────────┬──────────────┘
                                        │
        ┌───────────────┬───────────────┼───────────────┬────────────────┐
        ▼               ▼               ▼               ▼                ▼
   dsa/trie.py   dsa/inverted_    dsa/heaps.py    dsa/sorting.py  dsa/recommender.py
   prefix trie     index.py        bounded         merge sort      cosine similarity
   autocomplete    BM25 postings   min-heap        quicksort       + hybrid blend
        │               │               │               │                │
        └───────────────┴───────┬───────┴───────────────┴────────────────┘
                                ▼
                     data/products.json (126 products)
                     generated by data/seed.py
```

The frontend is a storefront shell (`templates/index.html`), a design-system stylesheet
(`static/style.css`), a duotone product-illustration library (`static/icons.js`), the
application logic (`static/app.js`) and a folder of product photographs
(`static/products/`), all served by the same Flask process.

| Module | Responsibility | Key entry points |
|---|---|---|
| `app.py` | Routes, startup indexing, facet computation, latency reporting | `home`, `api_catalog`, `api_search`, `api_suggest`, `api_product`, `api_recommend`, `api_facets` |
| `dsa/trie.py` | Prefix trie | `Trie.insert`, `Trie.autocomplete`, `Trie.stats` |
| `dsa/inverted_index.py` | BM25 index and prefix expansion | `InvertedIndex.add_document`, `InvertedIndex.search`, `InvertedIndex.idf` |
| `dsa/heaps.py` | Bounded min-heap for top-K | `TopKHeap.offer`, `TopKHeap.drain`, `heap_top_k` |
| `dsa/sorting.py` | Stable merge sort, quicksort | `merge_sort`, `quick_sort`, `sort_items` |
| `dsa/recommender.py` | Item vectors and personalised feed | `Recommender.similar`, `Recommender.recommend` |
| `data/seed.py` | Deterministic catalogue generator | `main` |

## Data structures & algorithms

| Feature | Structure / algorithm | Complexity | Where |
|---|---|---|---|
| Search-as-you-type | Prefix trie, completions harvested with a bounded min-heap | `O(P + K log K)` | `dsa/trie.py` |
| Product search | Inverted index with BM25 ranking (`k1=1.4`, `b=0.6`) | `O(postings of query terms)` | `dsa/inverted_index.py` |
| Partial-word search | Trie prefix expansion at half weight | `O(completions × postings)` | `InvertedIndex.search` |
| Results / trending | Bounded min-heap of size K | `O(N log K)` time, `O(K)` memory | `dsa/heaps.py` |
| Every sort control | Stable merge sort; quicksort (median-of-3, insertion cutoff) for comparison | `O(N log N)` | `dsa/sorting.py` |
| "You May Also Like" | Item-item cosine similarity over sparse vectors | `O(shared terms)` per pair | `dsa/recommender.py` |
| Personalised feed | Hybrid of taste profile, department affinity, trending prior | `O(candidates log K)` | `dsa/recommender.py` |

Size of the structures in the current build (also shown live in the "How Search Works"
panel): 2,466 trie nodes over 416 indexed phrases; 424 distinct index terms across 2,832
posting-list entries for 126 documents; 126 item vectors with 2,349 dimensions.

## API reference

All endpoints return JSON and report their own server-side latency as `took_ms`.

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/` | Storefront shell |
| `GET` | `/api/catalog` | Filtered, sorted, paginated catalogue |
| `GET` | `/api/search` | BM25 search with matched/unknown terms, expansions and suggestions |
| `GET` | `/api/suggest` | Trie autocomplete for a prefix |
| `GET` | `/api/product/<id>` | Product detail plus cosine-similar neighbours |
| `GET` | `/api/recommend` | Personalised hybrid feed |
| `GET` | `/api/facets` | Departments, price bounds, totals and index statistics |

**Shared query parameters** (`/api/catalog`, `/api/search`):

| Parameter | Type | Notes |
|---|---|---|
| `q` | string | Search query — `/api/search` only |
| `category` | string | Comma-separated department names |
| `min_price`, `max_price` | number | Inclusive price bounds |
| `min_rating` | number | Minimum star rating |
| `in_stock` | `1` | Restrict to available stock |
| `sort` | enum | `relevance`, `trending`, `newest`, `rating`, `price_asc`, `price_desc` |
| `page`, `per_page` | int | Pagination; `per_page` clamped to 6–60 |

**Endpoint-specific parameters:**

| Endpoint | Parameter | Notes |
|---|---|---|
| `/api/suggest` | `q` | Prefix to complete |
| `/api/recommend` | `viewed` | Comma-separated product IDs (up to the 12 most recent are used) |
| `/api/recommend` | `k` | Number of recommendations, clamped to 3–16 |

## Getting started

**Requirements:** Python 3.9+ (developed on 3.12) and Flask, pinned in [`requirements.txt`](requirements.txt). Nothing else.

```bash
# 1. Install the single dependency
pip install -r requirements.txt

# 2. (Optional) regenerate the catalogue — deterministic, same output every run
python data/seed.py

# 3. Run the storefront
python app.py
```

Then open **http://127.0.0.1:5000**.

<details>
<summary>Running in a virtual environment</summary>

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

</details>

To serve on a different host or port, edit the `app.run(...)` call at the bottom of
`app.py`.

## Usage

### In the browser

| Action | How |
|---|---|
| Search | Type in the header — suggestions appear as you type; `Enter` runs the search |
| Focus search | Press `/` |
| Filter | Use the left rail; on narrow screens press **Filters** |
| Open a product | Click a card title or image |
| Close any overlay | `Escape`, the close button, or the backdrop |
| Add to cart | **Add to Cart** on a card (appears on hover on desktop) |

Search, filters, sort and page are stored in the URL, so any view can be shared or
reloaded:

```
http://127.0.0.1:5000/?q=yoga&sort=price_asc
http://127.0.0.1:5000/?category=Books,Beauty&min_rating=4.5&in_stock=1
http://127.0.0.1:5000/?q=espresso#product-153
```

### From the command line

```bash
curl "http://127.0.0.1:5000/api/search?q=head&per_page=3"
curl "http://127.0.0.1:5000/api/catalog?category=Books&sort=rating&per_page=5"
curl "http://127.0.0.1:5000/api/suggest?q=skil"
curl "http://127.0.0.1:5000/api/recommend?viewed=150,144&k=6"
```

## Design system

The storefront is deliberately quiet: an ink-on-paper palette, one brand colour, and a
single illustration family instead of mixed hero art.

| Token | Value | Use |
|---|---|---|
| `--ink` | `#17191C` | Body text, announcement bar |
| `--paper` | `#FFFFFF` | Page background |
| `--mist` | `#F5F5F2` | Section fills, inputs |
| `--brand` | `#0E4B3C` | Primary actions, links, focus |
| `--gold` | `#A8823C` | Rating stars, "best seller" |
| `--sale` | `#B23A2F` | Sale badges and prices only |

**Type:** Instrument Serif for headlines, Public Sans for UI, with tabular numerals on
every price and count.

**Illustration:** `static/icons.js` holds 41 duotone line icons drawn on one 32-unit
grid, mapped to product types by keyword (matched against the product *type* first, since
names contain colour words such as "Cream" and "Sky"). Each department tints its tiles, so
the catalogue reads as one designed family. Books rotate through three variants and
cosmetics split semantically — dropper for serums, tube for SPF and moisturiser, bottle
for shampoo.

**Accessibility floor:** skip link, semantic landmarks, labelled icon buttons,
`:focus-visible` rings, focus restoration on overlay close, `Escape` handling
throughout, `aria-live` on result counts and toasts, and full `prefers-reduced-motion`
support.

## Verified behaviour

The following was checked against the running application rather than assumed:

- Every one of the 126 products resolves to a correct illustration — 41 distinct icons,
  zero fallbacks, zero mismatches (automated audit over the full catalogue).
- Search, autocomplete, prefix expansion (`head → headphones`, `espres → espresso`,
  `cast ir → iron`), deep-linked filters, sort, pagination, quickview, cart and the
  statistics panel all exercised in-browser with **zero console exceptions**.
- Cart arithmetic verified, including the free-shipping threshold recalculation
  (2 × $31.77 = $63.54; "Add $11.46 more for free shipping").
- Modal and drawer layout measured for overflow: no overlapping columns, no horizontal
  page overflow.
- Responsive behaviour confirmed at 390 px: no horizontal overflow, navigation collapsed
  to a menu, filter rail behind a toggle, two-column grid.
- Every element ID referenced by JavaScript exists in the markup, and every
  `aria-labelledby` target resolves at load.
- Server-side search latency measured between 0.09 ms and 5 ms across queries on the
  current catalogue.

## Limitations

Stated plainly, since this is a demonstration project:

- **No database.** The catalogue is a JSON file loaded at startup; carts live in
  `localStorage` and view history in `sessionStorage`. Nothing survives a cleared browser
  or is shared between users.
- **No authentication or checkout.** The cart is client-side and checkout is not
  connected — no payment is processed and no order is placed.
- **Sample data.** The 126 products, their prices, ratings and review counts are
  generated by `data/seed.py`. Sale badges and compare-at prices are derived
  presentationally on the client (roughly 30% of items, keyed off product ID), not real
  pricing data. Store policies, shipping copy and the newsletter are demo surfaces.
- **Photography with an illustration fallback.** 43 of the 55 product types show a real
  photograph sourced from Wikimedia Commons, restricted to CC0, Public Domain and plain
  CC BY — never ShareAlike — with the author, licence and source page for each image
  recorded in [`CREDITS.md`](CREDITS.md). The other 12 types keep the designed illustration:
  no suitable openly-licensed photo exists for them, and all eight book types are excluded
  on purpose because a real cover would misrepresent a title this catalogue invented.
  The app itself needs only Flask; regenerating the photos additionally needs Pillow
  (`pip install Pillow && python data/fetch_images.py`).
- **Photos are documentary, not studio packshots.** Commons has no e-commerce photography,
  so some images show the product in use or in a museum rather than on a seamless
  background, and a few are a loose rather than exact match to the product name.
- **Template caching.** Flask caches templates when `debug=False`; restart the server after
  editing `templates/index.html`.
